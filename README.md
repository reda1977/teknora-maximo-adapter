# أداة نقل البيانات: Maximo إلى تكنورا

أداة مستقلة تمامًا عن بوابة Teknora - ويزرد بمتصفح بيتصل بـ IBM Maximo
وبنظام تكنورا المركزي لإدارة الأصول، ويعرض البيانات المتاحة في Maximo
(منظمات، أشخاص، حرف، عمالة، مواقع، أصول، عدادات، أوامر شغل، قراءات
عدادات تاريخية، خطط عمل، صيانة وقائية)، وينقلها لتكنورا مع عرض تقدم حي
وتقرير نهائي بعدد السجلات الناجحة والفاشلة.

## التشغيل

### عن طريق Docker (الأسهل، خصوصًا على السيرفر)

```bash
docker compose up --build -d
```

بعدها افتح المتصفح على: http://localhost:8800 - تأكد الأول إن البورت ده
فاضي عندك (`sudo ss -tlnp | grep 8800`)، وعدّله في `docker-compose.yml`
لو محجوز لحاجة تانية.

### تشغيل مباشر (من غير Docker)

```bash
cd backend
pip install -r ../requirements.txt
python -m uvicorn main:app --reload --port 8800
```

بعدها افتح المتصفح على: http://localhost:8800

## متطلبات الشبكة

- الجهاز اللي بتشغّل عليه الأداة لازم يقدر يوصل لـ:
  - Maximo (مباشرة لو على نفس الشبكة، أو عن طريق أي نفق SSH/VPN شغال زي
    اللي مستخدم مع بوابة Teknora - استخدم نفس العنوان، مثلاً
    `http://172.18.0.1:9080/maximo` لو شغال من على الـ VPS).
  - تكنورا (`https://app.teknora-eam.com/api` أو أي رابط تاني حسب البيئة).

## ترتيب النقل (إجباري بسبب الروابط بين الجداول)

1. المنظمات والمواقع (Organizations + Sites)
2. الأشخاص (Persons)
3. الحرف (Crafts)
4. العمالة (Labor) - محتاجة الأشخاص والحرف يتنقلوا الأول
5. المواقع الفرعية (Locations)
6. الأصول (Assets)
7. العدادات (Meters - الكتالوج بس)
8. أوامر الشغل (Work Orders)
9. قراءات عدادات الأصول التاريخية - محتاجة الأصول تتنقل الأول
10. قراءات عدادات المواقع التاريخية - محتاجة المواقع تتنقل الأول
11. خطط العمل (Job Plans)
12. الصيانة الوقائية (PM) - محتاجة خطط العمل والأصول يتنقلوا الأول

**ملحوظة**: أوامر الشغل بتتنقل قبل خطط العمل (بناءً على طلب صريح)، فمبنبعتش
حقل `jpnum` (ربط أمر الشغل بخطة العمل) وقت نقل أوامر الشغل - الخطة لسه
مش موجودة في تكنورا وقتها، وإرساله كان هيفشل السجل بمخالفة مفتاح خارجي.
الربط ده مش موجود في النسخة الحالية، ومحتاج "مرحلة تحديث" منفصلة بعد نقل
خطط العمل لو حبيت تضيفه لاحقًا.

## أسماء Object Structures في Maximo

| النوع | Object Structure | حالة التأكيد |
|---|---|---|
| المنظمات والمواقع | `mxorganization` | ✅ متأكد فعليًا |
| الأشخاص | `mxperson` | ✅ متأكد فعليًا |
| الحرف | `mxcraft` | ✅ متأكد فعليًا |
| المواقع الفرعية | `mxoperloc` | ✅ متأكد فعليًا |
| الأصول | `mxasset` | ✅ متأكد فعليًا |
| أوامر الشغل | `mxwo` | ✅ متأكد فعليًا |
| خطط العمل | `mxapijobplan` | ✅ متأكد فعليًا (لاحظ بادئة "MXAPI" مش "MX") |
| الصيانة الوقائية | `mxapipm` | ✅ متأكد فعليًا (نفس نمط "MXAPI") |
| قراءات عدادات الأصول التاريخية | `mxmeterdata` | ✅ الاسم متأكد ("Meter Reading Definition")، بس حقول السجل نفسه (assetnum/metername/reading/readingdate) تخمين مبني على تسمية Maximo القياسية |
| قراءات عدادات المواقع التاريخية | `oslclocationmeter` | ⚠️ الاسم اتلقى فعليًا ("Oslc Location Meter"، مُستهلك بواسطة OSLC، نفس نمط `oslcmeter`)، بس حقوله (location/metername/lastreading/lastreadingdate) لسه تخمين |
| العدادات (الكتالوج) | `oslcmeter` | ⚠️ الاسم اتلقى فعليًا ("Oslc Meter Definition"، مُستهلك بواسطة OSLC)، بس حقوله (metername/metertype/uom) لسه تخمين |
| العمالة | `mxlabor` | ⚠️ تخمين مبني على نفس نمط التسمية ("Labor Definition")، فيه بديل موجود اسمه `MXAPILABOR` لو ده غلط |

لو أي اسم من دول اتغيّر أو غلط، هتلاقي رسالة الخطأ الحقيقية من Maximo
(زي `BMXAA4216E - Unknown Object`) في تقرير النقل النهائي بدل ما الأداة
تفشل بصمت.

## ملاحظات مهمة

- أسماء حقول تكنورا (في `backend/migration.py`) مبنية على أعمدة
  SQLAlchemy الحقيقية بتاعة تكنورا، لكن نقاط الحفظ (`/assets/save`،
  `/workorder/save`، `/jobplans/save`، `/labor/save`، `/pm/save`،
  `/person/save`، `/crafts/save`، `/meters/save`، `/meter-readings/save`،
  `/locmeter-readings/save`) في توثيق الـ API الحقيقي بتقبل أي شكل JSON
  (`additionalProperties: true`) من غير تحقق موثّق مسبقًا - يعني لو
  حقل معين مش متطابق 100%، هيظهر في قائمة "السجلات اللي فشلت"
  بالتقرير النهائي مع رسالة الخطأ الحقيقية من السيرفر، مش هيفشل بصمت.
- حقلين اتشالوا عمدًا من نقل الأصول (`vendor`, `po_num`) لأنهم مفاتيح
  خارجية (foreign keys) على جداول الموردين/أوامر الشراء اللي مش جزء من
  نطاق النقل ده - نقلهم غالبًا هيفشل لو الكود المرجعي مش موجود بالفعل
  في تكنورا.
- نقل العمالة (Labor) دلوقتي بيبعت `personid` و `craft_code` فعليًا
  (بعد ما بقى الأشخاص والحرف بيتنقلوا قبلها) - لو شخص أو حرفة معينة
  فشلت هجرتها بأي سبب، أي عامل بيشاور عليها هيفشل هو كمان ويظهر في
  التقرير، وده متوقع ومقصود (أفضل من إنشاء عامل بربط ناقص بصمت).
